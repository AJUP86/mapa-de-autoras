# Architecture & engineering audit — mapa-de-autoras

**Audit date:** 2026-07-25 · **Branch:** `development` (clean) · **Project position:** ~82% of MVP by stage count; staging live at `staging.mapadeautoras.com`; production deploy (9b) and launch prep (10) pending.

**Scope:** end-to-end review — architecture, frontend (Astro + React islands), backend (Supabase: schema, RLS, RPCs, Edge Functions), security, GDPR posture, accessibility, SEO, testing, CI/CD, dependency health, repo hygiene, and documentation/process. Reviewed against industry good practice for a solo-maintained, free-tier, public-facing product.

---

## 1. Executive summary

This is a well-architected small product with unusually strong documentation and decision discipline, undermined in three specific places: **Edge Function authentication**, **automated enforcement (CI/tests)**, and **accessibility of the core map feature**.

The foundational choices are sound and consistently executed: static Astro output means the public site survives a Supabase free-tier pause; the row-level-security model on the database is verified correct on every table (anon cannot read suggestions or subscriber emails); the design-token layer genuinely allows a one-file rebrand; secrets hygiene is clean across the entire git history — nothing to rotate. The staged-delivery process (ADRs, spec/plan pairs per stage, STATUS log, ops runbooks, PR-per-stage) is better than most funded teams manage.

However, the audit found **two critical vulnerabilities**, both in the Edge Function layer, where the platform JWT gate (`verify_jwt`) was disabled for a legitimate CORS reason but the replacement in-function gate was never made equivalent:

1. **`translate` accepts forged, unsigned JWTs** — anyone can mint a fake admin token and drain the DeepL quota.
2. **`notify_owner` is a fully unauthenticated open email relay** — the header check the migration promises was never implemented.

Alongside these, the repo has **no CI whatsoever** (only a Supabase heartbeat cron), `astro check` currently fails with 34 errors nobody noticed, only 28 unit tests exist across two files, and the map — the product's core feature — is **unusable by keyboard or screen reader** (WCAG 2.1.1 failure).

**Overall verdict: solid architecture, immature enforcement.** None of the critical items is expensive to fix; all of them should be fixed before the production deploy (Stage 9b).

## 2. Critical findings (fix before Stage 9b)

### C1 — `translate` Edge Function: authentication bypass

`supabase/config.toml:114-116` sets `verify_jwt = false`, and the in-function check ([translate/index.ts:33-59](../supabase/functions/translate/index.ts)) base64-decodes the JWT payload **without verifying the signature**, then trusts `app_metadata.role`. Anyone can send `Bearer x.<base64url of {"app_metadata":{"role":"admin"}}>.x` and use the DeepL proxy unauthenticated — quota exhaustion today, a billing liability on any paid plan. The function header comment and `supabase/README.md:120` both still claim `verify_jwt = true`, contradicting the actual config.

**Fix:** verify the signature in-function — call `supabase.auth.getUser(jwt)` (or verify HS256 against the project JWT secret) before trusting any claim. Handle the OPTIONS preflight explicitly; that was the original reason for disabling the platform gate.

### C2 — `notify_owner` Edge Function: unauthenticated open email relay

`config.toml:105-107` sets `verify_jwt = false`. Migration `0003_notify_owner_trigger.sql:18-19` says the trigger sends `X-Webhook-Source: postgres` "so the function can do a cheap header check" — **the function never reads that header**. The only gate is a payload-shape check ([notify_owner/index.ts:78-84](../supabase/functions/notify_owner/index.ts)), and CORS is `*`. Anyone can POST and send unlimited emails with attacker-controlled subject and body to the owner's inbox: Resend quota exhaustion, sender-reputation damage, and a phishing vector. `supabase/README.md:107` flags this as a known MVP gap — it must close before production.

**Fix:** enforce a shared-secret header (compared with a constant-time comparison), or move to Supabase Database Webhooks with a service-role bearer + `verify_jwt = true` (already the Stage 9b plan for `notify_submitter`). Drop `Access-Control-Allow-Origin: *` — no browser should call this endpoint.

### C3 — `notify_submitter`: accepts any bearer token; config not pinned (High)

[notify_submitter/index.ts:59-62](../supabase/functions/notify_submitter/index.ts) accepts **any non-empty Bearer token**, relying on platform `verify_jwt` — but the function has **no `[functions.notify_submitter]` block in `config.toml`**, so nothing in the repo pins that setting; a `--no-verify-jwt` deploy or dashboard toggle silently opens it. Even with platform verification on, the **public anon key passes the check**, so any visitor can invoke it with a suggestion UUID. Internal guards bound the blast radius, but the "only the webhook calls this" invariant does not hold.

**Fix:** add an explicit `verify_jwt = true` block in `config.toml`, and compare the bearer against `SUPABASE_SERVICE_ROLE_KEY` after `.trim()` (trimming solves the whitespace fragility that motivated relaxing the check). Also: the revert-on-Resend-failure at `:179` reopens the idempotency window (possible duplicate email on send-then-timeout) — add an attempt counter instead of a bare revert.

## 3. High-priority findings

### H1 — No CI pipeline

`.github/workflows/` contains only `heartbeat.yml` (a well-written weekly Supabase keep-alive). There is **no build, typecheck, test, or format gate on any PR or push** — and `development` is the auto-deploying branch on Cloudflare Pages, so an unchecked direct push goes straight to staging. Manual `astro check` invocations appear ten times across implementation plans; automation would replace all of them. This absence is how 34 type errors accumulated unnoticed (see H4).

**Fix:** one workflow on `pull_request` + `push`: Node 22, `npm ci`, `astro check`, `npm test`, `prettier --check .`, `astro build` (~2 min). Then require it via branch protection on `development` and `master`.

### H2 — `submit_suggestion` input validation and rate limiting gaps

- Only `authorName` has a server-side length cap (120); `booksText`, `note`, `submitterName`, `email` are inserted **unbounded** ([submit_suggestion/index.ts:120-124](../supabase/functions/submit_suggestion/index.ts)) — client `maxLength` is trivially bypassed, and the content is echoed into the owner's email.
- `verifyResp.ok` is never checked before `.json()` — a Cloudflare 5xx yields an unhandled throw / bare 500.
- Turnstile `hostname`/`action` are ignored, and one shared widget covers localhost + staging + production, so a token minted on staging is valid on production.
- No rate limiting anywhere; no idempotency (double-submit → two rows, two emails). CORS `*`.

**Fix:** mirror the client field limits server-side; check `verifyResp.ok`; assert Turnstile `hostname` against an allowlist; pin CORS to the two site origins; consider Cloudflare WAF rate rules on the function hostname.

### H3 — GDPR: `subscribers` table is an undisclosed data store with unimplemented consent flow

- Ticking the notify checkbox writes `email`, `locale`, and `confirm_token` into `subscribers` — a table the privacy notice **never mentions** (retention section covers only "Suggestions" and "Admin accounts").
- The consent copy is transactional ("let me know when I add this writer") but the table is commented as a "double-opt-in newsletter list" and migration `0010` documents intent to repurpose it — a purpose-limitation (Art. 5(1)(b)) problem.
- The double opt-in is **not implemented**: `confirm_token` is generated and stored, but no confirm endpoint, confirmation email, or status transition exists. No unsubscribe mechanism, no `List-Unsubscribe` header.
- No retention automation (submitter emails kept indefinitely) and no erasure tooling despite the notice promising deletion on request.
- `notify_owner` logs the full email body — including the submitter's address — to function logs when `RESEND_API_KEY` is empty, which is the current staging state.

**Fix:** stop writing to `subscribers` until a real newsletter consent ships (the notify flow reads from `suggestions`, not `subscribers`); add a `delete_personal_data(p_email)` admin RPC; add a scheduled job nulling `submitter_email`/`submitter_name` on old resolved suggestions; remove the PII log line.

### H4 — `astro check` fails with 34 errors; generated types unused

`tsconfig.json` includes `**/*`, pulling Deno Edge Functions into the Astro typecheck (25 noise errors) which buried 9 real `src/` errors ([promote.ts:49-50](../src/lib/promote.ts), test helper typing). Worse, **six hand-written row types shadow the generated `src/types/supabase.ts`** — and one of them is wrong: [authors.ts:13](../src/lib/authors.ts) declares `status: "read" | "discovery"`, missing the real enum value `currently_reading`, hidden by an `as unknown as` cast.

**Fix:** exclude `supabase/functions` from tsconfig; derive row types from `Database["public"]["Tables"][...]["Row"]` and delete the mirrors; fix the 9 errors; wire `astro check` into `build`/CI.

### H5 — Map is inaccessible by keyboard and screen reader (WCAG 2.1.1)

Every country path has `tabIndex={-1}` ([AuthorsMap.tsx:117](../src/components/AuthorsMap.tsx)), `global.css:37-41` removes focus outlines with `!important`, the container is `role="img"`, and **no alternative path to the data exists** (no country list/select/search). Keyboard and screen-reader users cannot reach any author data — the site's core function. Compounding it: status colors penguin-orange vs sage-green have a **1.04:1** contrast ratio (the classic deuteranopia confusion pair), there is no legend, and several text opacities (`text-ink/50`–`/60`, badge text, placeholders) fall below WCAG AA 4.5:1.

**Fix (cheap first):** a visible, localized country `<select>`/combobox that drives the same `selected` state; then real map semantics (per-country `aria-label` + `<title>`, `tabIndex={0}`, Enter/Space handling, `:focus-visible` ring); a legend with a non-color cue; raise low-opacity text to `/70`+.

### H6 — Every static page ships ~390 KB of JS for a nav bar

`AdminAwareNav` is `client:load` in [Base.astro:76](../src/layouts/Base.astro), pulling React + the Supabase client onto every page including pure-content ones (`/en/about/`). ~99.99% of visitors are not admins; they pay ~111 KB gzip and a visible nav skeleton pop-in for nothing.

**Fix:** render the nav statically in Astro; mount a tiny `client:idle` island only for admin affordances, gated behind a `localStorage` check before importing supabase. Highest-ROI performance change in the codebase.

## 4. Medium-priority findings

**Backend / data integrity**
- `promote_suggestion` RPC: correctly `SECURITY DEFINER` with pinned `search_path` and an `is_admin()` gate as the first statement (good) — but the suggestion UPDATE has **no state guard** (`status = 'pending'` not checked, zero-row match succeeds silently; a rejected suggestion can be flipped to approved; double-promote orphans the first author) and the duplicate-author check is a TOCTOU race with no backing unique index on `(lower(name), country_iso_a3)`.
- Function `EXECUTE` is never revoked from `PUBLIC`/`anon` — `is_admin()` saves you, but least-privilege says revoke.
- Migration `0010` copy-pastes the entire ~100-line RPC body from `0005` to change one line; the two copies will drift.
- Schema has exactly **one CHECK constraint** in total; no year sanity, no email shape, no URL scheme checks (`photo_url = 'javascript:…'` is storable). `0009` widened `iso_a3` from `char(3)` to `text` without a replacing format CHECK.
- Realtime: DELETE events bypass RLS visibility (anon learns deleted-author UUIDs — low impact, but the migration comment overstates the guarantee); publish→unpublish transitions are suppressed for anon subscribers so stale authors linger client-side; `replica identity` is default, which the known-placeholder reducers in [realtime-reducers.ts:162-188](../src/lib/realtime-reducers.ts) don't fully cope with (documented, ships wrong behavior when book-editing lands).
- `turnstile_verified` column is hardcoded `true` at its only write site — carries no information.
- No `updated_at`/audit columns on any table.
- **ADR 0003 documents a superseded security model** — it still says anon can INSERT into `suggestions`/`subscribers`, which migration `0002` deliberately reversed. The canonical data-model doc contradicts the code. Amend or supersede it.
- Confirmed: the known `authors.status` design flaw (set at promote, never updated; map filters lie once reading state changes) is real and the planned `books.status` refactor is documented but unstarted. Note: the planned enum values (`to_read/reading/read`) don't match current ones (`discovery/currently_reading/read`) — the backfill needs an explicit mapping, and Postgres can't remove enum values.

**Frontend**
- `CountryPanel` focus theft: effect depends on an unstable `onClose` prop, so every re-render (realtime event, filter click, pan) re-runs it and yanks focus back to the close button. Split into a stable keydown effect + mount-only focus effect.
- Country names render English-only on `/es/` (taken from world-atlas TopoJSON properties; `countries.name_es` exists in the DB but isn't wired).
- **All 85 `admin.*` keys in `en.json` are empty strings**, and `t()` returns `""` rather than falling back — empty `aria-label`s and tooltips for an admin browsing `/en/`. Fill them or add an empty-string fallback to the default locale.
- The dialog is not a real modal (no focus trap, background not inert, backdrop is a full-viewport `<button>` in the tab order); `MapFilter`'s `radiogroup` lacks the required arrow-key pattern.
- `renderBlock()` in [PrivacyPage.astro:24-42](../src/components/pages/PrivacyPage.astro) is an unescaped `set:html` sink — safe today (i18n JSON input), one refactor away from XSS. Escape before transforming.
- No canonical URLs, **no Open Graph/Twitter tags at all** (for an Instagram-distributed project this is the biggest marketing-facing gap), no 404 page, admin pages listed in `dist/sitemap-0.xml` and allowed by robots.txt.
- Map performance: 177 `<Geography>` elements re-render on every pan (no memoization), an `feDropShadow` over the whole landmass re-rasterizes per frame, and the 251 KB TopoJSON is inlined in the JS chunk instead of fetched from `/public`.
- `supabase.ts` falls back to `http://127.0.0.1:54321` on missing env vars with only a `console.warn` — a misconfigured production build **succeeds** and ships a dead site (this exact failure is recorded in the staging runbook). Throw when `import.meta.env.PROD`.
- No CSP (`public/_headers` absent) despite a third-party script and an HTML sink.
- Turnstile loader polls forever at 150 ms with no timeout or user-visible failure message.
- Duplication: `formatDate` ×3 (all using UTC — dates shift a day for Amsterdam evening submissions; use `Intl.DateTimeFormat`), `TranslateLabels` interface ×2, suggestion-context `<dl>` ×2, array-index React keys in `PromoteForm` book fieldsets (state remapping bug on remove); `PromoteForm.tsx` at 470 lines needs splitting.

**Tooling / hygiene**
- Prettier configured but never invoked (no script, no hook, no CI) and already drifting; **ESLint entirely absent** — no `react-hooks/exhaustive-deps` on a codebase built on `useEffect` + Realtime subscriptions (one cargo-culted `eslint-disable` comment exists at [MapSection.tsx:137](../src/components/MapSection.tsx)).
- No `vitest.config.ts`: no coverage, no jsdom, and the `~/*` tsconfig alias is unresolvable in tests (current tests dodge it with relative imports).
- Untested money paths: `promote.ts` error-string mapping (fragile `startsWith` parsing of RPC `raise` messages — a rewording silently degrades all admin error UX), `t.ts` fallback, i18n key parity, `submit_suggestion`, email rendering. A single Playwright smoke spec (map renders → suggest → thanks) would out-earn 20 more unit tests.
- **`supabase/snippets/Untitled query *.sql` are committed**: three Studio scratch files, two containing a real personal email and one being the live admin-grant escalation statement. Not credentials, but they don't belong in a public MIT repo. Remove, gitignore the directory, treat the email as disclosed (it stays in history).
- **README is materially stale**: says "no application code yet" (~1,700 lines exist), instructs pnpm (repo uses npm + `package-lock.json`), says Node ≥ 20 (staging requires Node 22 — Node 20 breaks Realtime), references a `/styleguide` route that no longer exists, and marks `src/`/`supabase/`/`.github/` as "(planned)".
- `.env.example` name mismatch: it defines `SUPABASE_SERVICE_ROLE` but the Edge Functions read `SUPABASE_SERVICE_ROLE_KEY` (both call sites default to `""` instead of throwing → confusing 401s locally); `SUPABASE_URL` requirement for local `functions serve` is undocumented; `PUBLIC_SITE_URL` and `SITE_URL` are two names for one value.
- `@astrojs/check` sits in `dependencies` instead of `devDependencies`; missing `check`/`format`/`verify` scripts; no `license` field in `package.json`.
- Launch checklist has stale unchecked sections (About page and nav consolidation are already shipped per git history) — doc drift in an otherwise disciplined system.

## 5. Low-priority / watch list

- **Supply chain:** `@vnedyalk0v/react19-simple-maps` is a single-maintainer personal fork sitting in the core render path. Pin the exact version; longer-term consider rendering directly with `topojson-client` + `d3-geo` (both already in the tree). Also pin `prettier-plugin-astro` to `^0.14` (bare `^0` allows breaking minors). Edge Functions import from esm.sh with no lockfile/integrity — consider vendoring.
- Migrations are not idempotent and have no down/rollback path; `heartbeat()` lacks a `search_path` pin (lint noise only).
- GitHub disables scheduled workflows after 60 days of repo inactivity — the heartbeat that prevents Supabase auto-pause can itself silently die. Add an independent pinger or uptime monitor.
- Realtime free-tier ceilings (200 concurrent connections) have no fallback-to-polling path; map has no loading or error state (outage renders as an empty grey world).
- Frontend auto-deploys on merge but migrations and Edge Functions deploy by hand — a drift window where new frontend meets old backend. A PR-template checklist item or a `supabase/functions/**`-triggered deploy workflow closes it.
- 16 merged `feature/*` branches linger on origin; environment setup is dashboard-clicked with no IaC (acceptable at this scale — the runbook is the compensating control).
- Project ref appears in tracked docs (not a secret, but it hands an attacker the exact hostname for the currently-open functions — moot once C1/C2 are fixed).

## 6. What is genuinely good

Worth stating explicitly, because it's the majority of the project:

1. **RLS design** — verified policy-by-policy: every table enabled, anon reads only published data, suggestions/subscribers fully closed, admin gate via non-self-mutable `app_metadata`. The `0002` tightening (moving anon INSERT behind a service-role Edge Function after Turnstile) shows real security reasoning.
2. **Secrets hygiene** — full-history scan clean; `.env.example` is exemplary; the heartbeat workflow uses proper secret indirection.
3. **Architecture-to-constraint fit** — static output + client-side data fetch means the public site survives free-tier pauses; the ADR trail explains every trade-off.
4. **Documentation/process** — 5 ADRs, dated spec+plan pairs per stage, STATUS.md session log, two excellent ops runbooks with hard-won gotchas, RAG.md index, PR-per-stage git history with conventional commits. Better than most funded projects.
5. **Code organization** — pure, tested reducers for map state and realtime patches; 11-line `[lang]` route adapters over shared page bodies; centralized Supabase client; zero TODO/FIXME markers; subscription/interval/listener cleanup is correct throughout (no leaks found).
6. **Design tokens** — raw values → semantic aliases → Tailwind theme; the one-file rebrand claim is true.
7. **Turnstile client integration** — token lifecycle (expire/error/reset/unmount) handled correctly; secret never touches the client.
8. **Dependency freshness** — nothing a major version behind.
