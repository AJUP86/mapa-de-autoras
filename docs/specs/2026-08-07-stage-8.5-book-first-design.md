## Why now (pre-launch, not post-launch)

The current data model is author-centric and has three confirmed bugs (verified in [docs/audit25072026.md](../audit25072026.md) §4):

- **(a)** A suggestion naming an author already in `authors` raises `duplicate_author` in the promote RPC and cannot be processed.
- **(b)** `authors.status` is set once at promote time and never updated, so the map's Leídas/Leyendo/Sugerencias filters lie the moment Danny actually reads a promoted book.
- **(c)** One suggestion covers one author with N books, so the submitter can only be told a single outcome.

The refactor changes the schema, so it must land **before** the production deploy — migrating an empty prod DB is trivial; migrating a live one later means a data migration under traffic. Sequenced after the security-hardening plan (Branches 1 + 2) so it lands on a repo with green CI, a clean `astro check`, and already-hardened Edge Functions.

## Core model

A **suggestion** is the envelope one visitor submits. It contains **one or more proposed books**, each with its own author + country + optional note, and each processed independently by the admin. We do not "promote a suggestion" — we **process** a suggestion by promoting / rejecting / marking-already-present the **books within it**. When every book is resolved, the admin clicks **Finish & notify**, the suggestion flips to `processed`, and one summary email goes to the submitter (if opted in).

```
suggestions (envelope)
  └─< suggestion_books (one row per proposed book)
        · proposed_author_name, proposed_country_iso_a3, proposed_book_title, note?
        · disposition: pending | promoted | rejected | already_present
        · reason? (rejected), linked_book_id? → books
```

## Scope

**In (Stage 8.5):**

- **Migration — enums:** drop `author_status`; add `book_status` (`to_read | reading | read`, default `to_read`); add `suggestion_book_disposition` (`pending | promoted | rejected | already_present`); recreate `suggestion_status` as (`pending | processed`).
- **Migration — tables:** drop `authors.status`; add `books.status`; new `suggestion_books` child table; slim `suggestions` down to the envelope; set `books` to `REPLICA IDENTITY FULL`; add unique index on `authors (lower(name), country_iso_a3)`. (`books.id` already exists as the PK since migration 0001 — the client `Book` type simply starts carrying it; no DB change.)
- **Migration strategy:** greenfield. Production is empty (countries only). Staging + local data is disposable — wipe and re-seed from an updated `supabase/seeds/dev-authors.sql` that includes `books.status`. No in-place backfill logic.
- **RPC:** rewrite `promote_suggestion` → `promote_suggestion_book` — upsert author by `(lower(name), country)`, insert the book at `to_read`, set the entry's disposition + `linked_book_id`. - **`submit_suggestion` rewrite:** accept the envelope + N-book payload; insert one `suggestions` row + N `suggestion_books` rows atomically; send the submit-acknowledgment email when opted in. **Folds in audit H2** (per-field server-side length caps, `verifyResp.ok` check, Turnstile hostname allowlist, CORS pinned to site origins) and **H3** (stop writing to `subscribers`).

- **Realtime:** reliable book INSERT/UPDATE/DELETE reducers keyed by `books.id` (enabled by `REPLICA IDENTITY FULL`); resolves the placeholder debt in `realtime-reducers.ts`.
- **Minimal admin book-status editing:** a simple admin list of books with an inline status dropdown per book; changes propagate to the public map via Realtime.

## Decisions

1. **Suggestion = envelope, books = independently-processed children.** Rejected the simpler "one suggestion = one book" model because it would force a visitor with 5 books across 3 authors to file 5 separate suggestions. The child table (`suggestion_books`) is the natural relational shape for per-book disposition, linking, and the per-book email lines.
2. **Single status collapse was reconsidered and dropped** in favor of two levels: `suggestions.status` (`pending | processed`) for the envelope, `suggestion_books.disposition` for each book. This is not the same as the old redundant `status`+`disposition` pair (which existed only because one row held many books).
3. **`submitter_email` stays required** (matches the current form, already disclosed in the privacy policy, and Danny always has a contact). Data-minimization (email-optional-unless-opted-in) considered and declined for launch — revisit if the privacy posture tightens. _Flagged for owner review._
4. **Two submitter emails, both opt-in-gated:** an acknowledgment on submit (inline in `submit_suggestion`, one-shot) and an outcome summary on finish-processing (webhook on `status → processed`, idempotent via `notified_at`).
5. **Explicit `Finish & notify`**, not auto-fire on last-entry-resolved — the email is outward-facing to a real person; Danny reviews all outcomes before it sends and controls timing.
6. **Greenfield migration** — no backfill; prod is empty and staging/local are disposable.
7. **Admin book-status editing is in-scope** (minimal) — without it, books freeze at `to_read` and the refactor delivers no visible payoff. Full CRUD stays deferred.
8. **`REPLICA IDENTITY FULL` on `books`** — required so Realtime UPDATE/DELETE payloads carry enough to match by id now that per-book status changes drive map color.

## Data model (target)

```sql
-- enums
create type book_status as enum ('to_read', 'reading', 'read');
create type suggestion_book_disposition as enum ('pending','promoted','rejected','already_present');
-- suggestion_status recreated as ('pending','processed')

-- authors: DROP status
-- books:   ADD status book_status not null default 'to_read';  REPLICA IDENTITY FULL
-- authors: unique (lower(name), country_iso_a3)

create table suggestion_books (
  id                      uuid primary key default gen_random_uuid(),
  suggestion_id           uuid not null references suggestions(id) on delete cascade,
  proposed_author_name    text not null,
  proposed_country_iso_a3 text not null references countries(iso_a3) on update cascade,
  proposed_book_title     text not null,
  note                    text,
  disposition             suggestion_book_disposition not null default 'pending',
  reason                  text,
  linked_book_id          uuid references books(id) on delete set null,
  display_order           int not null default 0,
  created_at              timestamptz not null default now()
);

-- suggestions (slimmed): id, submitter_email (not null), submitter_name, locale,
--   accepted_newsletter, status ('pending'|'processed'), notified_at, created_at.
--   Dropped: proposed_author_name, proposed_country_iso_a3, proposed_books_text,
--   note, promoted_author_id, reviewed_at, reviewer_notes, turnstile_verified.
```

RLS: no direct anon insert (writes go through the service-role `submit_suggestion`, as since migration 0002); admin manages `suggestions` + `suggestion_books`. `suggestion_books` reads gated to admin only (proposed content is not public until promoted into `books`).

## Components (units + responsibilities)

- **`submit_suggestion` (Edge Function)** — validate envelope + entries, verify Turnstile, atomic insert of envelope + N children, send ack email. In: HTTP POST from the form. Depends on: service-role client, Resend, Turnstile.
- **`promote_suggestion_book` (RPC)** — upsert author + insert book + resolve one entry. In: `(entry_id, author jsonb, book jsonb)`. `SECURITY DEFINER`, `is_admin()` gate first.
- **`notify_submitter` (Edge Function)** — render + send the per-book outcome email on `processed`. Idempotent.
- **`email.ts` (function-local)** — string tables + `renderSubmitAck()` + `renderOutcome()` for ES/EN. Pure.
- **`SuggestionForm.tsx`** — the repeater form. Owns entry list state; posts the payload.
- **`SuggestionReview.tsx`** — admin per-entry processing + Finish & notify.
- **`PromoteForm.tsx`** — reused, prefilled per entry (existing "from scratch" mode unchanged).
- **Admin book-status list** — minimal inline status editor.
- **`map-state.ts` (pure)** — `computeCountryStates` / `fillFor` from `books.status`. TDD.
- **`realtime-reducers.ts` (pure)** — id-keyed book reducers. TDD.
- **`authors.ts`** — `getCatalog()` reshaped to carry `books.status`; drop the hand-rolled author `status` type.

## Data flow

1. Visitor fills N book entries → `submit_suggestion` → 1 `suggestions` + N `suggestion_books` → (opt-in) ack email + `notify_owner` to Danny.
2. Danny opens the suggestion → processes each entry (Promote via prefilled `PromoteForm` / Reject+reason / Already-present) → each entry's disposition + `linked_book_id` set; promotes insert `books` at `to_read`.
3. Danny clicks **Finish & notify** → `suggestions.status → processed` → webhook → `notify_submitter` → one per-locale outcome email.
4. Over time, Danny moves books `to_read → reading → read` via the admin status dropdown → Realtime patches the public map color.

## Error handling

- `submit_suggestion`: envelope/entry validation → 400 `validation`; Turnstile fail → 400 `turnstile`; ack-email failure is non-fatal (log; the suggestion is already saved).
- `promote_suggestion_book`: `is_admin()` gate → `unauthorized`; entry not found / suggestion not `pending` → guarded no-op error surfaced in `promote.ts` error mapping; author upsert is race-safe via the unique index.
- `notify_submitter`: idempotent claim on `notified_at`; Resend failure increments an attempt counter (not a bare revert) to bound retries.
- Map: Realtime `CHANNEL_ERROR` / initial-fetch failure surfaces a non-empty error state (carried from the audit's resilience note; minimal here).
