# docs/ index (RAG)

Lookup table for everything in `docs/`. Keep this current when adding, renaming, or removing files.

| Filename | Short description | When to use |
| --- | --- | --- |
| `00-mvp-plan.md` | The **what** of the MVP: scope, stack at-a-glance, architecture overview, data model sketch, style direction, suggestion + admin workflow, map UX with filter, free-tier risks, verification plan, open questions. | Start here for any new contributor or new session. Read first when scoping a feature or checking whether something is in/out of MVP. |
| `01-implementation-plan.md` | The **how** and **in what order**: staged delivery plan (Stage 0–10), branching strategy (master/development/feature-NN), workflow rules, definition of done per stage, verification steps per stage. | Read before starting any implementation work. Use to pick the next stage, scope a branch, or check the "done" bar for the current stage. |
| `STATUS.md` | Running log: which stages are done, what last session shipped, project facts worth remembering (domain, owner-approved baselines), open decisions pending, and the resume-tomorrow command sheet. **Updated at the end of every working session.** | Read **first** when picking the project back up. The implementation-plan is the *target*; this is the *current position*. |
| `adr/0001-tech-stack.md` | Decision record for the technical stack — Astro, React island, Tailwind, Supabase, Turnstile, Resend, Cloudflare Pages, Capacitor (later). Lists alternatives considered and trade-offs. | Use when challenging or extending a stack choice ("why not Next.js?", "should we add X service?"), or before introducing a new dependency. |
| `adr/0002-style-guide.md` | "Literary Salon" brand decision — palette tokens (ink, parchment, bone, oxblood + 3 map tints, ochre, **penguin** vintage accent, sage), CSS-variable wiring for one-file palette swaps, typography (Fraunces + Inter), motion, map highlight scale, contrast checks. | Use when building or reviewing any UI surface, picking a new color, adding a font, tweaking the map fills, or proposing a visual change. |
| `adr/0003-data-model.md` | Decision record for the Supabase schema: 6 tables (countries, authors, books, book_links, suggestions, subscribers), `authors.status` enum (read/discovery) driving the map filter, RLS policy approach, indexes, locale-column strategy. | Use when writing migrations, designing queries, adding a new field, or modifying RLS. Source of truth for the schema shape. |
| `adr/0004-translation-strategy.md` | Decision record for the LLM-assisted translation flow in the admin form: DeepL via admin-only Edge Function, owner reviews/edits before save. Alternatives considered (LLM providers, auto-translate, manual). | Use when changing translation provider, adding a new bilingual field, or extending the Edge Function (e.g., formality toggle, translation memory). |
| `adr/0005-realtime-map-data.md` | Decision record for the architecture flip from "Astro build-time fetch baked into static HTML" (Stages 4-5) to "static shell + client-side fetch + Supabase Realtime subscription with granular patching" (Stage 9a-ii). Captures alternatives considered (auto-rebuild webhook, SSR hybrid, full SSR, polling). | Use when changing the public-data architecture, adding new Realtime subscriptions, or revisiting first-paint vs. real-time freshness trade-offs. |
| `30-ops/staging-deploy.md` | Staging deployment runbook — env-var inventory across Supabase + Cloudflare Pages + GitHub, key rotation procedures, Pages/migration rollback, free-tier auto-pause recovery, 10+ Stage-9a gotchas, 9b production checklist. | Read when operating on hosted staging, before starting Stage 9b, or when debugging a deploy/env-var issue. |
| `40-phase2-backlog.md` | Items that came up during MVP design sessions but were deferred to post-launch (post-Stage 10). Categorized by area (admin productivity, content/UX, ops, translation). Not prioritized — revisit after MVP ships. | Read when scoping a feature to confirm it's not already deferred. Add to this file when a brainstorming session generates a "later, not now" idea. |
| `specs/YYYY-MM-DD-<topic>-design.md` | Per-stage design specs written during brainstorming, before implementation. Capture scope, decisions table, architecture, component contracts, incremental delivery slices, and verification. Become historical reference once the stage merges. | Read at the start of a stage to align with the design that was approved. After the stage merges, the implementation plan + ADRs are the source of truth; specs are an audit trail of "why we built it this way." |
| `plans/YYYY-MM-DD-<topic>-implementation.md` | Per-stage step-by-step implementation plans. Each task lists exact files + checkbox steps with the actual code/commands. Companion to the spec of the same date; the spec is the "what / why," the plan is the "how, line by line." | Read at task-execution time to know exactly what to write, where, and how to verify. Update checkboxes as steps land. Once the stage merges, the plan is historical (handy for diff-walking later). |
| `RAG.md` | This file. Index of docs with short descriptions and when-to-use guidance. | Use to locate the right doc fast, or as the first read when arriving in `docs/`. Update whenever a doc is added, renamed, removed, or materially repurposed. |
